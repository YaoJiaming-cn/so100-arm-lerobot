# 术语表

硬件、电控、机器人学中涉及的术语，按字母序排列。

---

## B

### bit / 比特 (Binary Digit)

信息的最小单位，只有两种状态：0 或 1。

人类日常用十进制：每一位有 10 种可能（0~9），逢 10 进 1。计算机用二进制：每一位只有 0 和 1 两种可能，逢 2 进 1。

一个十进制数可以展开为 bit 序列。例：\(45 = 1 \times 2^5 + 0 \times 2^4 + 1 \times 2^3 + 1 \times 2^2 + 0 \times 2^1 + 1 \times 2^0\)，写成二进制就是 `101101`，共 6 个 bit。

任何信息——数字、文字、图片——都可以编码为 bit 序列。一个英文字母通常用 8 个 bit（1 字节）表示。汉字通常用 16~24 个 bit（2~3 字节）。

### 并行通信 (Parallel Communication)

多个 bit 在多根线上同时发送的通信方式。比如 8 根数据线，可以一次发 8 个 bit（1 字节）。

对比串行通信：串行只需 1 根信号线，成本低但速率慢；并行一次能发多个 bit，速率快但需要更多线，且线之间在高速下会互相干扰。现代长距离通信几乎全是串行（USB、以太网、HDMI 本质上都是高速串行）。

### 波特率 (Baud Rate)

串行通信中每秒传输的 bit 数，单位 bps（bits per second）。发送方和接收方必须约定相同的波特率，才能正确采样每个 bit。

例：波特率 1,000,000（1 Mbps）表示每秒发送 100 万个 bit，即每 1 微秒（μs）一个 bit。发送方每 1 μs 在信号线上放置一个电压（高 = 1，低 = 0），接收方按同一节奏每 1 μs 读一次电压。任何一方的时钟偏了，0/1 就会采错。

本项目舵机使用的默认波特率为 1,000,000（1 Mbps）。

### 数据增强 (Data Augmentation)

在训练过程中对原始数据做随机变换，生成"新的"训练样本，从而提高模型泛化能力。

常见变换：亮度/对比度/饱和度随机抖动、轻微旋转和平移、随机裁剪、锐度变化等。本质是让模型见过更多变体，防止背诵原图。

在本项目的 ACT 训练中，每张摄像头图片在输入模型前都会经过随机的亮度和仿射变换。

### 数据集划分 (Dataset Split / Train-Val-Test Split)

将数据集分为三个互不重叠的子集：
- **训练集 (Train)**：用来更新模型参数（反向传播时真正改变权重的数据）
- **验证集 (Validation)**：训练过程中定期评估，用来调超参数、选最佳 checkpoint
- **测试集 (Test)**：最后一次性评估，用来报告最终性能

对于模仿学习的小数据集（如 50 条），通常不划分，全量用于训练。验证方式改为**真机开环评估**——用训练集里没见过的初始条件让模型自己跑，看任务成功率。

### Epoch

在传统深度学习中，一个 epoch 表示模型把**整个训练集**从头到尾看了一遍。如果训练集有 1000 张图、batch_size=100，那么 1 epoch = 10 step。

LeRobot 的模仿学习训练不按 epoch 来，而是按**总步数 (steps)**——因为数据集较小（25000 帧），每步从全量数据中随机采样，不存在"看完一遍"的边界。

### 闭环控制 (Closed-loop Control)

控制系统的一种架构：持续测量输出值，与目标值比较得到误差，再用误差修正输出，形成反馈回路。

形式化描述：设目标值为 \(r\)，当前输出为 \(y(t)\)，误差 \(e(t) = r - y(t)\)。控制器根据 \(e(t)\) 计算出控制量 \(u(t)\)，驱动被控对象使 \(e(t) \to 0\)。

与**开环控制**相对：开环没有反馈，直接输出控制量，不检查结果。

## C

### CLI (Command Line Interface / 命令行界面)

通过键盘敲文本命令来操作计算机的方式。与之相对的是 **GUI（图形界面）**——用鼠标点击按钮和菜单。

CLI 的特点是：每次输入一行命令，回车后执行。所有操作通过文本完成，没有图形、没有鼠标。比如：

```bash
lerobot-train --policy=diffusion   # 训练模型
pip install lerobot                # 安装包
git commit -m "update"             # 提交代码
```

--policy 这种带双横线的叫**命令行参数**，用来告诉程序"怎么做"。类比：你在餐厅点菜，"辣度=微辣"就是给厨师的一个参数。

本项目所有操作都是 CLI——安装依赖、校准舵机、遥控、训练模型、评估。LeRobot 不提供图形界面。

### 串行通信 (Serial Communication)

将数据的每个 bit 按时间顺序逐一发送的通信方式。与之相对的是**并行通信**：多个 bit 在多根线上同时发送。

原理：一根信号线上，用电压高低区分 0 和 1。比如发 8 个 bit `01101001`，电压随时间变化的波形如下：

```
电压
5V ▐     ▐ ▐     ▐     ▐ ▐
   ▐ ▐ ▐ ▐ ▐ ▐ ▐ ▐ ▐ ▐ ▐
0V ├────────────────────────→ 时间
   bit:  0 1 1 0 1 0 0 1
```

发送方按波特率（如每秒 100 万个 bit）的节奏逐个放置电压，接收方按同样的节奏逐个读取。事先约定波特率来同步双方的时钟。

本项目舵机之间的通信就是 TTL 串行通信：12 个舵机共用一根信号线，通过 ID 地址区分目标。每一条指令（如"3 号转到 45°"）先编码为 bit 序列，再串行发送。

### 串口 (Serial Port / COM Port)

计算机上用于串行通信的物理接口。在 Windows 上设备管理器里显示为 `COM3`、`COM4` 等，在 Linux/macOS 上显示为 `/dev/ttyUSB0`、`/dev/ttyACM0` 等。

本项目控制板通过 USB 连接电脑后，电脑上会出现一个串口设备，Python 通过这个串口与舵机通信。

### 磁编码器 (Magnetic Encoder)

一种测量旋转角度的传感器。原理：电机轴末端贴一小块永磁体，轴转动时磁场方向随之旋转；磁编码器芯片靠 Hall 效应检测磁场方向，转换成数字角度值。

STS3215 使用的是 12-bit 磁编码器，一圈 360° 被均匀量化为 \(2^{12} = 4096\) 个离散值，分辨率约 0.088°。舵机的闭环控制就是靠它实时读取当前角度。

角度传感器还有别的技术路线（如光电编码器、电位器），磁编码器的优势是体积小、无接触磨损、抗油污。

## D

### 单片机 (MCU / Microcontroller)

一种集成在单颗芯片上的微型计算机。包含 CPU、RAM、存储（Flash / EEPROM）、通信接口（UART、I²C、SPI 等），全部在一块硅片上（SoC，片上系统）。只需供电就能独立运行程序。

和电脑 CPU（如 Intel Core i7）的本质一样——都是执行指令的图灵完备处理器。区别在于规模：单片机主频几十 MHz（比电脑慢约 100 倍），功耗毫瓦级，内存和存储以 KB 计而不是 GB，价格几毛到几块钱，通常不跑 Linux 而是裸机程序或 RTOS（实时操作系统）。

本项目的每个 STS3215 舵机内部就有一颗单片机，负责跑 PID 闭环控制——这是舵机被称为"智能舵机"的原因。

### 舵机 (Servo Motor)

一种能精确控制角位置的电机模组。内部包含：直流电机、减速齿轮组、角度传感器（编码器）、控制电路。

工作原理：接收目标角度 \(\theta_{\text{target}}\) 作为指令，内部传感器读取当前角度 \(\theta_{\text{current}}\)，计算误差 \(e = \theta_{\text{target}} - \theta_{\text{current}}\)，驱动电机转动直到 \(e \to 0\)。模型等价于一个角度层面的误差最小化系统。

本项目的舵机是**串行总线舵机**：通过 TTL 串行总线接收数字指令（如"转到 127.5°"），而非模拟信号（如 PWM 脉宽）。

型号：飞特 STS3215。单价约 100 元。

### 舵机控制板 (Servo Control Board)

上位机和舵机之间的协议转换器。一端通过 USB 连接上位机，另一端通过 TTL 串行总线连接舵机。将上位机发送的高级指令（如 Python 函数调用）转译为舵机能识别的串行协议。

本项目使用的控制板：飞特 Feetech SDK 板。

### 舵盘 (Servo Horn / Disk)

装在舵机输出轴上的圆盘，用于连接机械结构（如机械臂的关节件）。

每个舵机装两个舵盘：
- **主动舵盘**：装在舵机**带齿轮的那面**（花键输出轴）。内孔有齿，卡在花键上随电机一起旋转。扭矩从这里输出。
- **被动舵盘**：装在舵机**不带齿轮的背面**（光轴）。内孔光滑，纯粹起轴承支撑作用，不传递扭矩。

两个舵盘一左一右夹住关节，提供双支点——只有一个支点的话关节会晃动。类比：门的上合页和下合页。

舵机的输出轴不是普通圆轴，而是**花键（spline）**——轴表面有一圈细齿，主动舵盘的内孔有对应的齿槽，两者啮合。花键保证了舵盘和轴之间不会打滑。

## E

### EEPROM (Electrically Erasable Programmable Read-Only Memory)

一种断电后数据不丢失、可以按字节擦除和重写的存储器。和电脑硬盘/SSD 原理相似——都是非易失性存储——但容量极小（通常几十到几百字节，不是 GB 级别），且支持字节级读写（可以只改 1 个字节，不必擦一整块）。

在 STS3215 舵机中，EEPROM 用于存储断电后必须保留的配置参数：
- 舵机 ID（1 字节，0~254）
- 中位偏移量（homing offset，2 字节）
- 波特率（1 字节）
- PID 控制参数（各 1 字节）

TTL 总线上所有舵机的 ID 和波特率必须互不相同（避免冲突）且全部一致（否则无法通信），这些值存在 EEPROM 里保证每次上电自动恢复，不需要重新配置。中位校准时软件通过 TTL 总线向舵机发写 EEPROM 指令，新数据就永久存进去了。

## F

### FK / Forward Kinematics / 正运动学

正向运动学：已知 6 个关节各自转了多少度，算出末端夹爪在空间中的位置和朝向。

输入：6 个关节角度（舵机的编码器读数）。输出：一个空间位姿——夹爪中心在哪里 (x, y, z)，夹爪朝向哪个方向 (roll, pitch, yaw)。

计算依赖 URDF 模型提供的杆长和关节轴方向。本质上是一连串的矩阵乘法——每个关节对坐标系做一次旋转，6 次之后得到末端坐标系在世界中的位置。

类比：告诉你"手肘弯了 30°、肩膀抬了 45°"，你就能知道手掌在空中的哪个点。

是 Leader → EE 这一段。遥操作中 Leader 的 6 个舵机读数 → FK → 夹爪的空间坐标。

反向是 IK（逆运动学）。

## G

### 供电线 (Power Line)

舵机三根线中的红色线。为舵机提供驱动电机所需的直流电压（本项目为 7.4V 或 12V）。供电线和地线构成能量回路，传输功率（可达数瓦到数十瓦），与仅传信号的信号线有本质区别。

## H

### 航模舵机 (RC / Hobby Servo)

面向航模、遥控车船等爱好者的传统舵机品类。与本项目使用的串行总线舵机对比：

| | 航模舵机 | 串行总线舵机（本项目） |
|---|---|---|
| 控制信号 | PWM 脉冲宽度（模拟方式） | 数字指令（串行协议） |
| 接线 | 一个舵机占一根信号线 | 所有舵机共用一根信号线 |
| 旋转范围 | 通常 180°（有物理限位） | 360°（无物理限位），可设为连续旋转 |
| 信号线数 | 与舵机数成正比 | 不论多少舵机，始终 1 根信号线 |

航模舵机的 PWM 信号是全时持续的——它需要每 20ms 收到一次脉冲，脉冲宽度持续 1~2ms 来标记目标角度。而串行舵机是"发完即停"，只在需要更新角度时才发包。

## I

### 模仿学习 (Imitation Learning / Behavior Cloning)

一种机器人学习范式：人类通过遥操作演示任务（示教），模型学习"看到什么画面 → 应该做什么动作"的映射。

和传统分类/检测任务的区别：
- 输出不是"猫还是狗"，而是**连续的动作值**（6 个关节角度），是一个回归问题
- 数据不是互相独立的单张图片，而是**时序相关的序列**——前一帧的动作会影响后一帧的画面
- 评估方式不是 accuracy，而是**实际任务成功率**（机器人能不能自己完成抓取）

ACT (Action Chunking Transformer) 就是一种模仿学习算法——它一次预测未来 N 步的动作序列（chunk），而不是每次只预测下一步，从而让动作更流畅、减少抖动。

### IK / Inverse Kinematics / 逆运动学

逆向运动学：已知末端夹爪要去的空间位置和朝向，反算 6 个关节各自需要转多少度。

输入：一个空间位姿——夹爪要去的位置 (x, y, z) 和朝向 (roll, pitch, yaw)。输出：6 个关节的目标角度。

同一个目标位姿通常有多个解（关节可以有不同的摆法到达同一个位置），需要算法从中选出最优解（角度变化最小、远离关节限位等）。

是 EE → Follower 这一段。遥操作中 FK 算出的夹爪空间坐标 → IK → Follower 的 6 个舵机转动量。

正向是 FK（正运动学）。

## J

### 减速比 (Reduction Ratio / Gear Ratio)

齿轮组的输入转速与输出转速之比：

\[
N = \frac{\omega_{\text{in}}}{\omega_{\text{out}}}
\]

如减速比 345:1 表示电机转 345 圈，关节转 1 圈。

由功率守恒（忽略摩擦），力矩满足：

\[
\tau_{\text{out}} = N \cdot \tau_{\text{in}}
\]

即减速比 \(N\) 等于力矩放大倍率。代价是转速降低到 \(1/N\)。高减速比提供更大的输出力矩，但关节转速更慢。

### 接地线 (Ground / GND)

舵机三根线中的黑色线。

**理论：** 电压是相对量，没有绝对意义。说"信号线上是 5V"，意思是信号线比 GND 高了 5V。所有设备共用一根 GND 线作为参考零点——如果各自用各自的零点，A 设备的"5V"对 B 设备来说可能是 3.7V，通信就乱了。

**实践：** 所有舵机的黑线并联，接到同一根 GND 总线；控制板的 GND 引脚也接到这根线；电源的负极也接到这根线。于是所有设备共享同一个 0V 参考点。所谓"接地"，在这个项目里就是接到这根公共 GND 线上，不需要真的插到土壤里。GND 同时也作为电流的回流路径，和供电线形成闭合回路。

和家用插座里的地线（保护接地，防漏电的）是两回事。

## K

### 空心杯舵机 (Coreless Servo)

一种高端舵机，内部的直流电机转子没有铁芯——线圈做成极轻的空心圆筒状（像卷起来的纸筒），直接套在永磁体外面。

好处：
- 转动惯量极小 → 响应极快、加速极猛
- 没有铁芯的齿槽效应 → 转动顺滑、无顿挫感

缺点：功率小、怕过载、贵。

普通舵机（包括本项目的 STS3215）用的是有铁芯的有刷电机，不是空心杯。空心杯属于高端细分品类。

## M

### 模拟电路 / 模电 (Analog Electronics)

处理**连续信号**的电子技术。"模拟"指电压是真实物理量的直接类比，比如麦克风输出的电压随声波的空气振动连续变化，波形平滑无台阶。

与**数字电路**相对：模拟电路处理的是连续值（0~5V 之间任何电压都可以），数字电路只区分 0 和 1 两个离散状态。

大学工科课程里的"模电"就是这门课。

## P

### PWM 舵机 (PWM Servo)

使用 PWM（脉冲宽度调制）信号控制的传统舵机。信号线电压每隔 20ms 产生一个正脉冲，脉冲的**宽度**（持续时间）编码目标角度：

- 脉宽 1.0ms → 转到 0°
- 脉宽 1.5ms → 转到 90°（中位）
- 脉宽 2.0ms → 转到 180°

```
5V ▐           ▐           ▐
   ▐           ▐     ▐     ▐     ▐
   ▐           ▐     ▐     ▐     ▐
0V ├───────────┼─────┼─────┼─────┤→ 时间
   │←── 20ms ──→│
                  ←1.5ms→ (90°)
```

这是一个纯模拟协议——角度由脉冲宽度这个**连续量**表达（1.0~2.0ms 之间任何宽度都有效）。与之相对，本项目的串行总线舵机用数字协议——角度被量化成 0~4095 的整数，精确编码为 bit 序列传输。

PWM 舵机最大的局限：每个舵机需要独占一根信号线（因为每个周期都要持续发脉冲）。多关节机器人如果用 PWM 舵机，线束会非常臃肿。

## Q

### 全双工 / 半双工 (Full-duplex / Half-duplex)

描述通信链路中数据传输模式的术语。

**全双工：** 两根数据线，一根专门发送（TX）、一根专门接收（RX）。两端可以**同时**说话，互不干扰。就像两个人各拿一部手机打电话——两边能同时说、同时听。

```
A ───TX───→ B
A ←──RX─── B
```

USB 和 UART 串口默认都是全双工的。

**半双工：** 只有一根数据线，同一时刻只能有一端在发送。就像对讲机——说完要松按钮对方才能说。12 个舵机全挂在这一根线上，控制板发指令时所有舵机静默，某个舵机回数据时所有其他设备闭嘴。

```
A ←── 一根线 ──→ B
  同一时刻只能一个方向
```

舵机的 TTL 总线是半双工。控制板的作用之一就是把 UART 的全双工（TX+RX 两根线）转换成舵机总线的半双工（一根线）。

## S

### 数字电路 / 数电 (Digital Electronics)

处理**离散信号**的电子技术。所有信息被量化为 0 和 1（bit），不考虑中间电压。TTL 就是这样一种数字逻辑标准：高于某阈值就是 1，低于某阈值就是 0。

优点是抗干扰——信号衰减一点、噪声混进来一点，只要不越过阈值就不影响结果。缺点是无法表达连续值（必须经过模数转换）。

大学工科课程里的"数电"就是这门课。

### 数据包 (Data Packet)

通信协议中一段有结构的 bit 序列。通常包含若干字段，如：

```
[起始标志] [目标地址] [指令长度] [指令内容] [校验和]
```

每个字段有固定的含义和 bit 长度，发送方按格式填充后串行发送，接收方按同样的格式逐字段解析。

类比：一张有固定格式的表格，每一格写什么有规定，拿表的人知道第一个格子是地址、第二个是内容。数据包就是在信号线上发送的"电子表格"。

TTL 总线上的所有舵机都会收到数据包，但只有地址字段匹配的那台舵机才读内容并执行。其余忽略。

### 上位机 (Host Computer)

主从架构中运行高级程序、发送指令的计算机。在本项目中指运行 Python 代码的个人电脑。

与**下位机**（控制板、舵机等直接控制硬件的设备）相对。数据流方向：

```
上位机 → (USB) → 控制板 → (TTL) → 舵机
```

### 伺服电机 (Servomotor)

"伺服"是"servo"的音译，意为"跟随/服务"。广义上，只要能通过闭环反馈精确控制位置、速度或力矩的电机都叫伺服电机，涵盖从几块钱的塑料舵机到几十万元的工业重载电机。

本项目用的 STS3215 **舵机**属于伺服电机里最便宜、最小型的品类，是 servo 的子集。工业伺服电机一般用无刷电机 + 高精度编码器，一个要几千到几十万元。

通俗类比：伺服电机 = 所有"能听话走到指定位置"的电机总称。舵机 = 其中 100 块钱一个、航模和机器人爱好者用的那类。

## T

### TTL (Transistor-Transistor Logic)

一种数字电路的电压标准：
- 逻辑 0：0V
- 逻辑 1：5V（或 3.3V）

在本项目中，"TTL 线"指采用此电压标准的串行通信线，即 UART 信号以 TTL 电平传输（区别于 RS-232 等使用 ±12V 的标准）。

### TTL 总线 / 串行总线 (TTL Bus / Serial Bus)

多个设备共享同一组 3 根线（供电、接地、信号）的拓扑结构。所有设备并联，组成**总线网络**。

通信机制：每个舵机有唯一 ID（地址），主机发送 `[目标地址, 指令]` 格式的数据包，只有 ID 匹配的设备响应，其余忽略。

本质是**主从协议 + 总线拓扑**：一个主机，多个从机，共用通信介质。

## U

### USB 转串口 (USB to Serial / USB to UART)

一种芯片模块，把 USB 协议转换成 UART 串口协议。

**为什么需要：** 电脑只有 USB 口，舵机控制板只有 UART 接口——物理接口和通信协议都不兼容。USB 是一种高速、复杂的现代协议（设备枚举、数据包封装），而 UART 是一种极简的老协议（裸 bit 流，按波特率收发）。转换芯片（如 CP2102、FT232）在中间充当翻译——收到 USB 数据包后拆掉 USB 的封装，取出原始 bit 流，从 UART 端按舵机能懂的节奏发出去。

同时，芯片的驱动程序在电脑上创建一个**虚拟 COM 口**（Windows 上显示 `COM3`，Linux 上显示 `/dev/ttyUSB0`）。上层软件以为自己打开了一个老式串口，实际数据是经 USB 线传输的。这就是 Python 代码里写 `port="COM3"` 就能和舵机通信的原因——驱动已经帮程序把 COM 口和背后的 USB 设备绑定好了。

### URDF (Unified Robot Description Format / 统一机器人描述格式)

一种用 XML 格式描述机器人几何结构的文件。包含杆件长度、关节类型、坐标变换关系、质量、惯性等信息。

对 FK 和 IK 而言，URDF 是**最关键的数据源**——它告诉运动学求解器：每根杆多长、关节轴朝哪个方向转、上级关节在哪。没有 URDF，FK 就算不出夹爪在空间中的位置。

类比：URDF 是机械臂的"解剖图"。FK/IK 就是在这个解剖图上运行的算法。

本项目的 URDF 文件来自 [TheRobotStudio/SO-ARM100](https://github.com/TheRobotStudio/SO-ARM100) 仓库，文件名 `so101_new_calib.urdf`。

### 信号线 (Signal Line)

- 半双工：同一根线分时用于发送和接收
- 采用 TTL 电平的串行协议

## Z

### 直流电机 (DC Motor)

最简单的电动机。两端施加直流电压，转子就持续旋转。特点：
- 转速和电压近似正比（电压越高转越快）
- 负载越大，电流越大（需要更大的力 → 需要吸入更大的电流）
- 断电后靠惯性滑行，不会立刻停

直流电机只知道"通电就转、断电就停"，不知道当前转到哪个角度，也无法停在指定位置。所以单独一个直流电机无法做机械臂关节——需要加上角度传感器和控制器，构成**闭环控制**，这就是**舵机**的思路。

直流电机相当于舵机内部三大组件中的"肌肉"部分（提供动力的原件）。剩下两个——传感器和控制器——负责"感觉"和"决策"。

### 自由度 (Degree of Freedom / DOF)

描述系统位形（configuration）所需的最少独立坐标数。

**从坐标系理解：** 平面上一个点需要 2 个坐标——直角坐标 \((x, y)\) 或极坐标 \((r, \theta)\)，两者等价且都恰好 2 个参数。三维空间中同理——直角坐标 \((x, y, z)\) 或球坐标 \((r, \theta, \phi)\)，恰好 3 个参数。坐标系可以换，参数个数换不了，因为这是空间本身的维数决定的：

\[
\dim(\mathbb{R}^2) = 2,\quad \dim(\mathbb{R}^3) = 3
\]

- 空间中的一个质点：DOF = 3（x, y, z）
- 空间中的一个刚体：DOF = 6（3 个平移 + 3 个转动）

**机械臂的每个转动关节提供 1 个 DOF。** 3 个关节时，末端位置由 3 个关节角唯一确定——这叫正向运动学，映射 \((\theta_1, \theta_2, \theta_3) \mapsto (x, y, z)\)，刚好覆盖位置。但要控制末端**朝向**，还需要 3 个 DOF，共 6 个，因为末端的位形空间是 \(SE(3)\)，维数为 6：

\[
\mathbb{R}^3 \times SO(3) \cong SE(3),\quad \dim = 6
\]

若关节数少于 6，则末端的可达位形集合是真子集，存在某些位置/朝向无法实现。

本项目机械臂有 6 个关节（shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper），即 6 个 DOF。

### 主动臂 (Leader Arm)

遥操作系统中由人类手持操作的那只机械臂。舵机的齿轮被拆除（或使用低减速比），关节几乎无阻力，可轻松拖动。舵机仅作为角度传感器使用，读取关节位置并发送给从动臂。

英文也称 Master Arm 或 Teacher Arm。

### 从动臂 (Follower Arm)

遥操作系统中执行任务的那只机械臂。保留完整齿轮和高减速比，输出高扭矩。实时接收主动臂传来的关节角度指令，复现相同的运动。

英文也称 Slave Arm 或 Student Arm。

### 总线拓扑 (Bus Topology)

所有节点共享同一通信介质的网络拓扑。任一时间只有一个节点发送数据，其余节点接收。通过地址字段区分目标。

本项目中 12 个舵机共用同一组 TTL 线，构成总线拓扑。

### 中位校准 (Neutral Calibration / Homing)

给舵机的原始角度值和物理含义建立对应关系的过程。

**为什么需要：** 舵机内部的编码器只能报告一个 0~4095 的原始数值，但"值 2048 对应的物理角度"在各个舵机之间并不统一——出厂差异、装配误差、减速齿轮的机械偏移都会造成不一致。不校准的话，"转到 45°"这个指令在 6 个关节上对应 6 个不同的实际角度，机械臂根本没法建模。

**怎么做：**
1. 手动将每个关节摆到其运动范围的**中间位置**（中位），此时关节处于自然居中状态
2. 读取这个位置对应的编码器原始值，记录为 **homing offset**
3. 之后软件把原始值减去这个 offset，就能得到"以中位为零点"的角度值
4. 再校准每个关节的**运动范围**（最小角和最大角对应的原始值）

**效果：**
- 所有关节有了统一的"零位"参考（中位 = 0°）
- 主动臂和从动臂处于相同物理姿态时，报告的关节角度完全一致——这是遥操作的基础
- 在 A 机器人上训练的策略可以迁移到 B 机器人上运行，因为两台的标定结果是标准化的

## Y

### 有刷电机 (Brushed DC Motor)

直流电机的一种。转子上的线圈通过**碳刷**和**换向器**与外部电源连接——碳刷是压在换向器上的两块石墨，换向器随转子旋转，在不同角度自动切换电流方向，保证转子持续朝一个方向转。

优点：结构简单、成本低（几块钱到几十块）、控制容易（给直流电压就转）。
缺点：碳刷会磨损（有寿命限制）、摩擦产生火花和噪声、效率偏低。

舵机（STS3215）内部就是一颗小型有刷直流电机。

---

## W

### 无刷电机 (Brushless DC Motor / BLDC)

直流电机的一种，没有碳刷和换向器。转子是永磁体，定子是线圈。外部**电子调速器（ESC）**根据转子位置精确切换线圈的通电顺序，替代机械换向。

优点：无碳刷磨损（寿命长）、效率高、功率密度大、无火花噪声。
缺点：需要独立的 ESC 控制器（贵且复杂）、整体成本高。

舵机几乎不用无刷电机。高端工业伺服电机和无人机常用无刷。
